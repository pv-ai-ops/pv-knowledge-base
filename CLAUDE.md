## Project Overview

This is a **Pharmacovigilance (PV) Knowledge Base** built with Hexo static site generator, specifically designed for pv-ai-ops organization. The site focuses on drug safety, AI applications in pharmaceutical surveillance, and technical analysis.

**Key Architecture:**
- **Static Site Generator**: Hexo 7.3.0 with Next theme (modern, search-enabled)
- **Deployment**: GitHub Pages via GitHub Actions (doc-page → gh-pages branch)
- **Content Management**: Custom content-inbox workflow for automated publishing
- **Mixed Content**: Supports both Markdown articles and interactive HTML applications

## Site Configuration

- **Live URL**: https://pv-ai-ops.github.io/pv-knowledge-base/
- **Primary Branch**: `doc-page` (source code and content)
- **Deployment Branch**: `gh-pages` (auto-generated by GitHub Actions)
- **Theme**: Next (configured in `_config.next.yml`)
- **Language**: Chinese (zh-CN) with English technical terms

## Content Workflow & Commands

### Core Publishing Workflow

The site uses a unique **content-inbox** system for streamlined content management:

1. **Content Staging**: Place new content in `content-inbox/` subdirectories
2. **Automated Processing**: `npm run publish` processes and moves content
3. **Local Preview**: Automatically starts development server
4. **Production Deploy**: `npm run deploy` triggers GitHub Actions

### Essential Commands

```bash
# Content Publishing (Most Common)
npm run publish          # Process content-inbox files, auto-delete originals, start preview

# Development & Preview  
npm run preview          # Clean build + start development server
npm run server           # Start server only (port 4000)

# Build & Deploy
npm run build           # Generate static files (hexo generate)
npm run clean           # Clear build cache and public folder
npm run deploy          # Git commit/push to trigger GitHub Actions deployment

# Manual Hexo Commands
hexo new post "Title"   # Create new post with Front Matter template
hexo new page "name"    # Create new page
```

## Content-Inbox System

**Directory Structure:**
```
content-inbox/
├── markdown/    # .md blog articles
├── html/        # Interactive HTML applications  
└── assets/      # Images, documents, resources
```

**Automated Processing (`scripts/publish.js`):**
- **URL-Safe File Naming**: Automatically converts file names to URL-friendly format using `createSafeFileName()`:
  - `vs.` → `-vs-`, colons `：:` → `-`, spaces → `-`
  - Preserves Chinese characters while removing problematic symbols
  - Prevents GitHub OAuth callback URL mismatch issues with Gitalk comments
- **Markdown**: Auto-adds Front Matter (title, date, tags), moves to `source/_posts/` with safe file names
- **HTML**: Preserves interactivity, moves to `source/` root (skip_render enabled) with safe file names  
- **Assets**: Copies to `source/assets/`
- **Cleanup**: Deletes original files from inbox after successful processing

## Special Configurations

### HTML Content Handling
- Interactive HTML files bypass Hexo rendering via `skip_render: ["*.html"]` in `_config.yml`
- Allows complex JavaScript applications (Chart.js, interactive visualizations)
- Files in `source/` root are accessible at site root (e.g., `/interactive-app.html`)

### Gitalk Comment System
- **Configuration**: Located in `_config.next.yml` under `gitalk:` section
- **OAuth Setup**: GitHub OAuth App configured for `pv-ai-ops/pv-knowledge-base`
- **URL Matching**: File naming automation prevents OAuth callback URL mismatch issues
- **Proxy**: Uses CORS proxy for GitHub API access
- **Language**: Chinese (zh-CN) interface

### GitHub Actions Deployment
- **Trigger**: Push to `doc-page` branch
- **Process**: Install deps → Build static files → Deploy to `gh-pages`
- **Target**: `./docs` directory becomes GitHub Pages root (configured as `public_dir` in `_config.yml`)
- **Auto-deploy**: No manual intervention needed after push

- **Config**: `_config.next.yml` (separate from main Hexo config)
- **Features**: Dark mode, local search, reading progress, social links
- **Customizations**: Medical/AI color scheme (#06B6D4), Chinese font support

### File Management
- **Generated Files**: `docs/` directory (configured as `public_dir`, not gitignored for GitHub Pages)
- **Source Control**: Source files in `content-inbox/` and `source/`
- **Asset Handling**: Copy to `source/assets/` for proper Hexo processing
- **URL Structure**: Permalink format `:year/:month/:day/:title/` creates dated URL paths

### Automated File Naming System
- **Purpose**: Prevents OAuth callback URL mismatch issues with special characters
- **Function**: `createSafeFileName()` in `scripts/publish.js`
- **Rules**: Preserves Chinese characters, converts spaces and special symbols to URL-safe format
- **Applies to**: Both Markdown articles and HTML applications automatically

### Typical Issue Resolution
- **Gitalk comments not loading**: Check if article URL contains special characters; republish to apply safe naming
- **GitHub Pages not updating**: Verify `docs/` directory is committed and pushed
- **HTML apps not working**: Verify `skip_render` includes the file pattern
- **Missing search**: Ensure `hexo-generator-searchdb` is installed
- **Build failures**: Run `npm run clean` before `npm run build`

## AI Integration Requirements

### Image Recognition Protocol (ULTRATHINK)

**CRITICAL**: All image identification and analysis MUST use Gemini instead of the Read tool directly:

- **For screenshot analysis**: Use `chrome_screenshot` tools to capture pages, then send to `mcp__gemini-cli__ask-gemini` with the image path
- **For file image analysis**: Always use `@file_path` syntax with Gemini CLI instead of Read tool for image files
- **Image content description**: Let Gemini provide detailed visual analysis, layout description, and content interpretation
- **Technical diagrams**: Use Gemini to extract technical information, architectural details, and visual patterns from technical graphics

**Example workflow**:
```bash
1. Take screenshot → chrome_screenshot or playwright_screenshot
2. Send to Gemini → ask-gemini with @image_path 
3. Get detailed visual analysis → comprehensive description and insights
```

**Never use Read tool for images** - it bypasses the intelligent visual analysis capabilities that Gemini provides.
